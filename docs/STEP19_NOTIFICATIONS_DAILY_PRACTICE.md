# Step 19 — Notifications, Reminders & Daily Practice

## Design in one paragraph
Today's plan is a short checklist (cybersecurity / communication / interview) built **deterministically** from the existing
personalization engine and stored once per user per local day. Each task is started through the module that already owns
that practice type and then *linked* to the plan. Task/plan completion, minutes practiced, streak and the summary are all
read from the real finished sessions — nothing is recorded twice. Reminders are generated lazily and idempotently.

## Rules
* **Streak / active-day rule:** a local day counts when at least one practice activity was *completed with a result*
  (scored cybersecurity/communication/interview/pressure/voice session, or a finished CTF). Opening the app, starting or
  abandoning a session never counts. Several sessions on a day count once. Days follow `preferred_timezone` (UTC fallback);
  changing the timezone rebuilds the cached day set. Days outside `practice_days` neither break nor extend a streak.
  Dates in the future are ignored. A streak stays alive until the end of "today".
* **Plan stability:** one `daily_practice` doc per (user, date) (unique index). Rebuilt only on explicit request or when the
  duration/difficulty setting changes — and only while nothing has been started.
* **Gemini:** not used for planning (no extra API calls). Questions are still generated by the existing Step 17 engine
  when a task starts.
* **Reminders:** `reminder_config` (settings) → `reminder_rules` (what is due, pure) → `notification_service.create_if_absent`
  (unique `dedupe_key` per period) → API / browser delivery. Max 3 per local day, ordered high → low priority.
* **Expiry:** daily/lapse reminders expire end-of-day / 3 days, weakness/interview/communication 7 days, progress/streak
  30 days (Mongo TTL index + reads ignore expired). No session/history data is ever deleted.

## API
`GET /notifications`, `GET /notifications/unread-count`, `POST /notifications/sync`, `POST /notifications/read-all`,
`POST /notifications/{id}/read`, `DELETE /notifications/{id}`;
`GET /daily-practice`, `GET /daily-practice/streak`, `POST /daily-practice/start`,
`POST /daily-practice/tasks/{kind}/link`, `POST /daily-practice/regenerate`, `POST /daily-practice/complete`.

## Database
New: `notifications` (indexes: user+dedupe_key unique, user+created_at, user+is_read, TTL on expires_at),
`daily_practice` (user+date unique), `practice_streaks` (user unique; cache of active dates).
Extended: `users.preferences` gains 10 optional fields with defaults (no migration needed).
