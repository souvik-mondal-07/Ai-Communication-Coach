# DSA content seeding plan

Status of the Phase 24 bank (see `docs/dsa-coverage.md`, generated by `python -m app.services.dsa.cli coverage`):

* All 54 subtopics of the 10 syllabus topics have at least 4 validated questions, so every syllabus line is traceable to usable practice questions.
* 4 is a floor, not depth: 6 subtopics have exactly 4 questions and 16 have 4–5. Long sessions on those subtopics will repeat questions.
* 166 of 347 questions are verified only by manual review (a written justification, no machine check). They are concentrated in conceptual, scenario
  and complexity questions, where the answer is theory rather than a computed value. The other 181 are machine-checked: 109 by a reference
  computation re-derived at every start-up, 31 output snippets, 26 reference solutions and 15 fill/fix option sets executed by the test suite.

## Next passes (in priority order)

1. Raise every subtopic with 4–5 questions to 8+, favouring trace and output-prediction questions (these are machine-checkable).
2. Add a second coding exercise to each of: linked lists (header/circular, doubly), stacks (Polish conversion), queues (deque), BST deletion, heap insertion, double hashing, Bellman–Ford.
3. Convert manual-review complexity questions to instrumented checks (count loop iterations for several n and fit the growth rate).
4. Add Gemini-assisted *drafting* only behind the same validation gate: generated questions stay `draft` (never served) until a reference computation or executed solution confirms them.

Questions are never labelled as appearing in a specific company's exam; the validator rejects such claims.
